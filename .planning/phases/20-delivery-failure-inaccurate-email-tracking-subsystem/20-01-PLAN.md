**Phase:** 20

**Status:** In Progress  

---

## Overview

Build an end-to-end delivery failure and bounce intelligence system for StrokeCRM. In cold outreach, inaccurate, invalid, or deleted recipient addresses result in either immediate SMTP rejections (synchronous) or Google Mailer-Daemon Non-Delivery Reports (NDR / asynchronous bounces from `mailer-daemon@googlemail.com` and `postmaster@*`). This phase equips StrokeCRM to automatically detect, parse, and categorize both types of delivery failures, atomically mark records as `BOUNCED` with diagnostic status codes (e.g. `550 5.1.1 Address not found`), permanently disarm pending drip cadence steps for bad addresses, and provide operators with a dedicated Delivery Failures tracker and 1-click Inaccurate Leads CSV export.

## Tasks

### Task 1: SQLite Schema Migrations & Bounce Tracking Infrastructure
**Files:** `server/db.js`, `server/databaseService.js`  
**Description:** Add bounce tracking columns to `database_records`, `contacts`, and `campaigns` tables, create `bounce_logs` table, and update database statistics calculations.
**Acceptance Criteria:**
- [ ] Add `bounce_reason TEXT`, `bounce_code TEXT`, `bounce_type TEXT`, and `bounced_at TEXT` to `database_records` and `contacts`.
- [ ] Add `bounced_count INTEGER DEFAULT 0` to `campaigns`.
- [ ] Create `bounce_logs` table (`id`, `campaign_id`, `database_record_id`, `contact_id`, `recipient_email`, `bounce_type`, `bounce_code`, `diagnostic_code`, `raw_reason`, `source`, `created_at`).
- [ ] Update `databaseService.getIncludedStats` to track and return `bounced` count alongside `sent`, `failed`, and `replied`.

---

### Task 2: Inbound Mailer-Daemon / NDR Bounce Parser
**Files:** `server/replyScannerService.js`  
**Description:** Implement robust asynchronous bounce detection in `replyScannerService.js` to catch Google Mailer-Daemon (`mailer-daemon@googlemail.com`), Postmaster (`postmaster@*`), and RFC 3464 delivery status notifications.
**Acceptance Criteria:**
- [ ] Detect bounce senders and subjects (`Delivery Status Notification (Failure)`, `Undelivered Mail Returned to Sender`, `Mail delivery failed`, `Returned mail`).
- [ ] Parse message bodies and RFC 3464 DSN headers to extract the target recipient email address (`Final-Recipient`, `** Address not found **`, `Delivery to the following recipient failed permanently`).
- [ ] Extract diagnostic error codes (e.g., `550 5.1.1`, `554 5.7.1`, `Host or domain name not found`) and classify `bounce_type` (`HARD` vs `SOFT`).
- [ ] Match extracted email against `database_records` / `contacts`.
- [ ] Atomically update lead record to `status = 'BOUNCED'`, store bounce details, set `next_step_scheduled_at = NULL` to permanently disarm subsequent drip steps, and insert into `bounce_logs`.

---

### Task 3: Outbound Synchronous Dispatch Error Classifier
**Files:** `server/queueService.js`  
**Description:** Enhance `queueService.js` worker to classify SMTP dispatch errors at send time into permanent bounces vs temporary connection failures.
**Acceptance Criteria:**
- [ ] When Nodemailer encounters SMTP recipient rejections (codes `550`, `553`, `Invalid recipient`, `No recipients defined`, `mailbox unavailable`), classify as `BOUNCED` (`HARD`).
- [ ] Store error diagnostic in `bounce_reason`, `bounce_type`, `bounce_code`, and set `next_step_scheduled_at = NULL`.
- [ ] Update campaign stats (`failed_count`, `bounced_count`).
- [ ] Ensure transient errors (timeouts, rate limits) remain `FAILED` for retry rather than falsely marked as permanent bounces.

### Task 4: API Endpoints for Inaccurate Leads & CSV Export
**Files:** `server/index.js`  
**Description:** Add dedicated REST API endpoints to fetch bounced leads and stream downloadable CSV reports.
**Acceptance Criteria:**
- [ ] `GET /api/campaigns/:id/bounces`: Returns bounced records for a campaign with recipient email, name, bounce reason, code, type, and timestamp.
- [ ] `GET /api/campaigns/:id/bounces/export`: Streams an RFC 4180 CSV export of inaccurate leads for list scrubbing.
- [ ] `GET /api/databases/:id/bounces` and `GET /api/databases/:id/bounces/export`: Database-level bounce inspection and export.
