# Phase 19: Template Assignment & Multi-Variant Bindings in A/B Testing - Plan

**Phase:** 19  
**Milestone:** v4.0  
**Requirements:** [AB-01, AB-02, AB-03]  
**Status:** In Progress  

---

## Overview

In the current A/B Testing Studio, users must manually type or copy/paste subject lines and email bodies for Variant A and Variant B. If they have already crafted and saved email templates in the Templates Studio with specific formatting and file attachments, they cannot directly assign those templates to their A/B testing variants. Furthermore, there is no side-by-side comparative spam scoring or detected variable audit between variants prior to launch, and `queueService.js` only pulls email attachments from the primary campaign `template_id`.

This phase adds:
1. Direct template assignment to Variant A and Variant B via interactive pickers in `ABTestingView.jsx`.
2. Dynamic comparative metadata: side-by-side spam risk scores, word count, character count, and detected personalization variable tags.
3. Backend database support for `template_id_b` on campaigns and transactional saving in `server/index.js`.
4. Dynamic attachment and template resolution in `server/queueService.js` ensuring Variant B contacts receive attachments from Variant B's assigned template.

---

## Tasks

### Task 1: Backend Database & Schema Support (`server/db.js`, `server/index.js`, `server/queueService.js`)
- [ ] Add `template_id_b` column migration to `campaigns` table in `server/db.js`.
- [ ] Update `server/index.js`:
  - `GET /api/campaigns/:id/ab-stats`: Return `template_id_a` and `template_id_b`, along with associated template names and attachment summaries.
  - `POST /api/campaigns/:id/ab-save`: Accept and persist `template_id_a` (stored as `template_id`) and `template_id_b` in the `campaigns` table.
  - `POST /api/campaigns/:id/duplicate`: Ensure `template_id_b` is replicated during campaign cloning.
- [ ] Update `server/queueService.js`:
  - Dynamically resolve `templateIdToUse` based on variant: if `variant === 'B'` and `campaign.template_id_b` is present, resolve attachments via `templateService.getMailAttachments(campaign.template_id_b)`, with fallback to `campaign.template_id`.

### Task 2: Frontend A/B Testing Studio Overhaul (`client/src/components/ABTestingView.jsx`)
- [ ] Load templates via `GET /api/templates` and fetch the selected campaign's details (including attached database headers).
- [ ] Add interactive template selector above Variant A and Variant B with options:
  - `-- Custom Copy (No Template Bound) --`
  - List of saved templates with badge indicating attachment count.
- [ ] On template selection:
  - Populate variant subject and body with the selected template's copy.
  - Bind `template_id_a` / `template_id_b`.
- [ ] Build side-by-side comparative deliverability radar:
  - Real-time spam score & risk rating (calling `/api/templates/spam-check`).
  - Detected variable tags (`{{FirstName}}`, etc.) highlighting missing personalization.
  - Word count and character count comparison with winner indicator.
  - Dynamic variable chips from the campaign's attached database schema.
- [ ] Save handler transmitting `template_id_a` and `template_id_b` to `/api/campaigns/:id/ab-save`.

### Task 3: Verification & Test Execution
- [ ] Run `npm run build` in `client/` to verify zero compile or bundle errors.
- [ ] Execute an automated test script validating template binding, saving, and `ab-stats` serialization.

---

## Success Criteria
1. Selecting a template in Variant A or Variant B instantly populates the subject line and body and records the template ID.
2. Comparative deliverability scorecards display live spam scores, detected variable chips, and word counts.
3. Saving preserves both `template_id` and `template_id_b` in SQLite.
4. Outbound dispatch resolves attachments for Variant B using `campaign.template_id_b`.
