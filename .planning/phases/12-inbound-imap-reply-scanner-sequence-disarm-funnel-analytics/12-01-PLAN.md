<objective>
Implement the Inbound IMAP Reply Scanner, Sequence Disarm, and Funnel Analytics for StrokeCRM.
Enable automatic and on-demand detection of incoming email responses from leads, atomically halt pending follow-ups (`CANCELLED_REPLIED`), filter auto-responders, provide manual override controls, render a visual conversion funnel, and generate downloadable CSV audit exports.

Purpose: Eliminate the risk of sending follow-up emails to leads who have already replied, and give operators clear conversion metrics across every step in their outreach sequence.
Output: Backend reply scanner service, SQLite reply audit schema, API endpoints, visual conversion funnel card, and manual lead action controls.
</objective>

  <action>
    1. In `server/db.js`:
       - Create `reply_logs` table:
         ```sql
         CREATE TABLE IF NOT EXISTS reply_logs (
           id INTEGER PRIMARY KEY AUTOINCREMENT,
           campaign_id INTEGER,
           database_record_id INTEGER,
           contact_id INTEGER,
           sender_email TEXT NOT NULL,
           subject TEXT DEFAULT '',
           snippet TEXT DEFAULT '',
           in_reply_to TEXT,
           message_id TEXT,
           is_auto_reply INTEGER DEFAULT 0,
           received_at TEXT NOT NULL,
           created_at TEXT NOT NULL,
           FOREIGN KEY (campaign_id) REFERENCES campaigns(id) ON DELETE CASCADE
         );
         ```
       - Run safe column migrations:
         - `replied_at TEXT` on `database_records` and `contacts`
         - `reply_count INTEGER DEFAULT 0` on `campaigns`
    2. Create `server/replyScannerService.js`:
       - `resolveImapConfig()`:
         - Checks `settings.active_provider`.
         - If `custom_domain`: returns `{ host: settings.custom_imap_host, port: Number(settings.custom_imap_port) || 993, secure: ..., auth: { user: settings.custom_imap_user, pass: settings.custom_imap_pass } }`.
         - If `gmail_app_password`: retrieves active account and returns `{ host: 'imap.gmail.com', port: 993, secure: true, auth: { user: account.email, pass: account.app_password } }`.
       - `scanInboxForReplies({ campaignId = null })`:
         - Instantiates `new ImapFlow({ ...imapConfig, logger: false })`.
         - Connects to IMAP server, acquires lock on `INBOX`.
         - Searches messages since 14 days ago.
         - Filters auto-responders (`Auto-Submitted`, `X-Autoreply`, `Precedence`, subject regex).
         - Matches sender email or `inReplyTo` against `database_records` (and `contacts`).
         - For valid replies:
           - In an atomic transaction:
             - Updates contact `status = 'REPLIED'`, `replied_at = receivedAt`, `next_step_scheduled_at = NULL`.
             - Inserts into `reply_logs` (deduplicating by `message_id`).
             - Updates `campaign.reply_count`.
         - Returns summary `{ scanned: count, matchedReplies: n, autoRepliesIgnored: m, lastScannedAt }`.
       - `markLeadRepliedManually(databaseRecordId, campaignId)`:
         - Atomically sets `status = 'REPLIED'`, `replied_at = now`, `next_step_scheduled_at = NULL`.
       - `cancelFollowupsManually(databaseRecordId, campaignId)`:
         - Sets `next_step_scheduled_at = NULL` and marks `status = 'CANCELLED'`.
    3. In `server/index.js`:
       - Add `POST /api/replies/scan`: triggers `scanInboxForReplies()`.
       - Add `GET /api/campaigns/:id/replies`: returns reply logs for campaign.
       - Add `POST /api/campaigns/:id/records/:recordId/mark-replied`: manual disarm.
       - Add `POST /api/campaigns/:id/records/:recordId/cancel-followup`: manual follow-up cancellation.
       - Add background interval polling every 5 minutes when active campaigns exist.
  </action>

         - Sets headers:
           - `Content-Type: text/csv; charset=utf-8`
           - `Content-Disposition: attachment; filename="campaign-${campaign.id}-audit-${date}.csv"`
