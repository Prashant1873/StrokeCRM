<objective>
Implement the Multi-Step Drip Sequence Engine and Builder Studio for StrokeCRM campaigns.
Allow campaigns to schedule up to 3 automated follow-up steps with customizable delay offsets (days/hours), template binding, dynamic variable interpolation, organic conversation threading (`In-Reply-To` / `References`), and scheduled timestamp queue dispatch.

Purpose: 60-70% of cold email conversions occur on follow-up emails. This automation ensures timely, organic in-thread follow-ups are dispatched safely without manual intervention or third-party email automation SaaS fees.
Output: SQLite drip step schema, API endpoints, queue scheduling engine with RFC 2822 threading, and React DripSequenceStudio in the Campaign Cockpit.
</objective>

           campaign_id INTEGER NOT NULL,
           step_number INTEGER NOT NULL, -- 1 = Initial, 2 = Follow-up 1, 3 = Follow-up 2

  <files>server/queueService.js, server/databaseService.js</files>

  <action>
    1. In `server/queueService.js`:
       - Enhance `dispatchSingleEmail`:
         - Accept optional `stepConfig` (with `step_number`, `thread_reply`, `subject_a`, `body_a`, `template_id`) and `initialMessageId` and `initialSubject`.
         - If `stepConfig && stepConfig.step_number > 1`:
           - Use the step's subject and body (or bound template).
           - If `stepConfig.thread_reply`:
             - Inject `mailOptions.headers['In-Reply-To'] = initialMessageId;`
             - Inject `mailOptions.headers['References'] = initialMessageId;`
             - If subject does not start with `Re: `, format as `Re: ${initialSubject || mailOptions.subject}`.
           - Add `mailOptions.headers['X-Drip-Step'] = String(stepConfig.step_number);`
         - Return `{ messageId, variant, subject, stepNumber }`.
       - Update `runCampaignWorker(campaignId)`:
         - Query next eligible contact respecting scheduled delay:
           ```sql
           SELECT * FROM database_records 
           WHERE database_id = ? 
             AND status = 'PENDING' 
             AND included = 1
             AND (next_step_scheduled_at IS NULL OR next_step_scheduled_at <= ?)
           ORDER BY 
             CASE WHEN current_step > 1 THEN 0 ELSE 1 END,
             id ASC 
           LIMIT 1;
           ```
         - If contact is found:
           - Fetch the corresponding step from `campaign_drip_steps` for `contact.current_step` (fallback to Step 1 / campaign template).
           - Dispatch email with threading headers if follow-up step.
           - On success:
             - Record in `email_logs` with `step_number = contact.current_step`.
             - Check if next step exists:
               `SELECT * FROM campaign_drip_steps WHERE campaign_id = ? AND step_number = ? AND is_active = 1` for `contact.current_step + 1`.
             - If next step exists:
               - Calculate delay: `((nextStep.delay_days * 86400) + (nextStep.delay_hours * 3600)) * 1000` ms.
               - `const nextScheduled = new Date(Date.now() + delayMs).toISOString();`
               - Update contact: `current_step = current_step + 1, status = 'PENDING', next_step_scheduled_at = nextScheduled, initial_message_id = COALESCE(initial_message_id, result.messageId), sent_at = nowIso`.
             - If NO next step exists:
               - Mark `status = 'SENT', next_step_scheduled_at = NULL, sent_at = nowIso`.
         - If NO immediately due contact is found:
           - Check if there are future scheduled contacts:
             ```sql
             SELECT COUNT(*) as count, MIN(next_step_scheduled_at) as earliest 
             FROM database_records 
             WHERE database_id = ? AND status = 'PENDING' AND included = 1 AND next_step_scheduled_at > ?;
             ```
           - If future scheduled contacts exist:
             - Do NOT complete campaign!
             - Set `job.isWaitingSchedule = true; job.lastLog = 'Waiting for scheduled follow-ups. Next send at ' + new Date(earliest).toLocaleTimeString();`
             - Update campaign status to `WAITING_SCHEDULE`.
             - Sleep for 30s (`interruptibleSleep(30000, jobId)`) and loop.
           - If NO pending contacts and NO future scheduled contacts exist:
             - Mark campaign `COMPLETED` and stop.
       - Update `getCampaignQueueStatus`:
         - Return step counts: `step1_sent`, `step2_sent`, `step3_sent`, `step2_scheduled`, `step3_scheduled`.
       - Update `sendTestEmail` to support previewing any step number.
    2. In `server/databaseService.js`:
       - Ensure `reopenUnusedDatabase` resets `current_step = 1, next_step_scheduled_at = NULL` on fresh campaign reset.
  </action>
