<objective>
Implement universal custom domain email connectivity (SMTP outbound dispatch and IMAP inbound access) alongside existing Gmail accounts, with smart provider presets, dual verification testing (handshake + live test-send), and campaign-level sender selection.

Purpose: Allow founders and businesses to send outreach directly through their custom business domain emails (e.g. `user@company.com`) or alternative providers without third-party email service lock-in.
Output: Backend endpoints, SQLite schema extensions, SettingsView Custom Domain tab, and Campaign Preflight sender account selector.
</objective>

    2. In `server/db.js`:
       - Extend `settings` table schema / initialization to store:
         - `active_provider` (TEXT DEFAULT 'gmail_app_password')
         - `custom_sender_name` (TEXT DEFAULT '')
         - `custom_sender_email` (TEXT DEFAULT '')
         - `custom_smtp_host` (TEXT DEFAULT '')
         - `custom_smtp_port` (INTEGER DEFAULT 587)
         - `custom_smtp_secure` (INTEGER DEFAULT 0)
         - `custom_smtp_user` (TEXT DEFAULT '')
         - `custom_smtp_pass` (TEXT DEFAULT '')
         - `custom_imap_host` (TEXT DEFAULT '')
         - `custom_imap_port` (INTEGER DEFAULT 993)
         - `custom_imap_secure` (INTEGER DEFAULT 1)
         - `custom_imap_user` (TEXT DEFAULT '')
         - `custom_imap_pass` (TEXT DEFAULT '')
       - Ensure `db.getSettings()` and `db.updateSettings()` safely serialize and return these fields.
    3. In `server/index.js`:
       - Add `POST /api/auth/test-custom-smtp`:
         - Accepts `{ host, port, secure, user, pass }`.
         - Validates port numbers (default 587 if missing).
         - Creates a transient `nodemailer.createTransport({ host, port, secure: Boolean(secure), auth: { user, pass } })`.
         - Calls `await transporter.verify()`.
         - Returns `{ success: true, message: "SMTP server handshake verified successfully." }` or `{ success: false, message: error.message }`.
       - Add `POST /api/auth/test-custom-imap`:
         - Accepts `{ host, port, secure, user, pass }`.
         - Instantiates `new ImapFlow({ host, port, secure: Boolean(secure), auth: { user, pass }, logger: false })`.
         - Calls `await client.connect(); await client.logout();`.
         - Returns `{ success: true, message: "IMAP connection verified successfully." }` or `{ success: false, message: error.message }`.
       - Add `POST /api/auth/send-test-email`:
         - Accepts `{ host, port, secure, user, pass, sender_name, sender_email, recipient_email }`.
         - Dispatches a formatted verification message to `recipient_email`.
         - Returns `{ success: true, message: "Test email delivered successfully." }`.
       - Update `POST /api/settings/account` and `GET /api/auth/status` to report `active_provider` and custom domain status.
  </action>
  <verify>Run `node -e "require('./server/db'); console.log('DB Schema OK')"` and check that `server/index.js` starts without syntax errors.</verify>

<task type="auto">
  <name>Task 2: Update queueService Transport Resolver for Custom Domain Dispatch</name>
  <files>server/queueService.js</files>
  <read_first>server/queueService.js, server/db.js</read_first>
  <action>
    1. In `server/queueService.js`:
       - Create `resolveTransporter(campaignSenderOverride = null)`:
         - Fetches current settings from `db.getSettings()`.
         - Resolves the target provider: `campaignSenderOverride || settings.active_provider || 'gmail_app_password'`.
         - If `provider === 'custom_domain'`:
           - Constructs a Nodemailer transporter using `settings.custom_smtp_host`, `settings.custom_smtp_port`, `settings.custom_smtp_secure === 1 || settings.custom_smtp_secure === true`, and `auth: { user: settings.custom_smtp_user, pass: settings.custom_smtp_pass }`.
           - Resolves `from` header as: `"${settings.custom_sender_name} <${settings.custom_sender_email || settings.custom_smtp_user}>"`.
         - If `provider === 'oauth2'`:
           - Uses existing Google OAuth2 transport resolver.
         - Else:
           - Uses existing Gmail App Password transport resolver.
       - Update queue sending execution loop to utilize the resolved transporter and `from` address.
       - Ensure `info.messageId` is stored in queue records for thread tracking.
  </action>
  <verify>Run `node -e "require('./server/queueService'); console.log('Queue service loaded')"`</verify>
  <acceptance_criteria>
    - `server/queueService.js` resolves custom SMTP transport when `active_provider === 'custom_domain'` or when a campaign specifies custom domain override.
    - Outgoing emails sent via custom domain properly populate the custom sender name and address.
  </acceptance_criteria>
  <done>Queue dispatcher can seamlessly send emails through custom domain SMTP relays.</done>
</task>
